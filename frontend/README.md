# 공통하늘 프런트엔드

선택한 1–3개 관측지에서 함께 보이는 카탈로그 천체의 시간–고도 곡선을 비교하는 React 19 + TypeScript 단일 페이지 앱입니다.

개발 서버는 `/api` 요청을 `http://127.0.0.1:8000`으로 전달합니다. 저장소 루트에서 환경 활성화 후 아래 명령을 사용할 수 있습니다.

```powershell
npm run dev --workspace frontend
npm run build --workspace frontend
npm run lint --workspace frontend
npm run test --workspace frontend
```

`관측 가시성` 탭에는 Narrabri, Pyeongchang, Fushan 관측지 선택과 좌표, UTC 시간창, 계산 간격, 최소 고도와 3C 카탈로그 선택이 있습니다. 한 곳부터 세 곳까지 선택할 수 있으며 모든 선택 관측지가 같은 샘플에서 기준 고도 이상일 때 공통 가시로 판정합니다.

`LOFAR DR3 카탈로그` 탭은 ASTRON 비동기 TAP 서비스를 통해 `lotss_dr3.main_sources`를 조회합니다. 카탈로그 전체의 144 MHz 밝기 순 목록과 ICRS 중심 좌표·반경을 지정하는 cone search를 전환할 수 있으며, 정렬 기준·방향과 TOP 10–1000개 범위를 선택하고 실제 실행될 고정 ADQL을 읽기 전용으로 미리 볼 수 있습니다. 각 검색 방식의 입력·결과·페이지는 독립적으로 유지되고, 한 번 받은 결과는 브라우저에서 25개씩 나누어 표시하므로 페이지 이동은 TAP 작업을 다시 만들지 않습니다.

LoTSS의 `ILTJ...` 좌표 기반 ID와 `S/M/C` 전파 형태 코드는 항상 보존합니다. 5″ 이내 SIMBAD 위치 후보가 있으면 3C·NGC·IC 같은 친숙한 별칭을 우선 표시하고 SIMBAD 천체 유형, 대응 거리와 신뢰 구간을 함께 보여 줍니다. 이는 위치 기반 후보이지 확정 식별은 아닙니다. 외부 이름·유형 보강에 실패해도 원래 LoTSS 검색 결과와 선택 기능은 유지됩니다.

오래 걸리는 요청은 화면의 응답 대기를 중단하거나 같은 조건으로 재시도할 수 있습니다. 화면 대기 중단은 원격 job의 즉시 취소를 보장하지 않습니다. 서버 작업은 계속될 수 있으며, 완료되거나 제한시간에 도달하면 정리됩니다. 두 검색 방식의 결과에서 선택한 source는 좌표, 144 MHz 플럭스와 식별 metadata snapshot으로 관측 설정에 유지됩니다. 메인 탭에서는 기본 3C와 불러온 LOFAR 천체를 모두 세로 목록에서 개별 선택·해제할 수 있고, LOFAR 체크를 해제해도 목록에 남아 다시 선택할 수 있습니다. `목록 삭제`를 눌렀을 때만 불러온 항목 자체가 사라집니다. 기본 3C 천체와 LOFAR source를 합해 최대 25개까지 계산할 수 있습니다.

상세 target 그래프 아래에는 선택한 카탈로그 천체 중 전체 시간창의 하나 이상의 계산 샘플에서 모든 관측지가 동시에 기준 고도 이상인 target 전체의 시간–고도 개요가 이어집니다. 개요 패널의 체크 목록에서 플롯할 target을 개별 선택하거나 모두 표시·숨길 수 있습니다. 이 선택은 상세 target 카드와 API 계산 결과를 변경하지 않으며, 새 계산 결과를 받으면 관측 가능한 target 전체가 다시 기본 선택됩니다. 그래프에는 해당 천체의 전체 시간창 궤적을 표시하며, 시간창의 모든 샘플에서 보인다는 뜻은 아닙니다.

결과의 각 target 카드와 선택 target 상세 정보에는 시간창 내 최장 공통 가시 구간을 함께 표시합니다. 이 값은 연속 계산 샘플의 첫 시각과 마지막 시각 사이의 경과 길이이며, 샘플 사이 모든 순간의 가시성을 보장하는 값은 아닙니다. 단일 가시 샘플은 지속시간 미확정으로, 최장 구간이 시간창 경계에 닿으면 창 밖은 미계산으로 구분합니다.
