BURSTT 사이트별 빔 시각화용 자료 조사·추출 요청
수신: BURSTT main server에서 작업하는 Codex 또는 Claude

목적
FUS, PYC, LTN, OGW의 실제 운용 설정에 근거해 각 사이트의 빔 중심,
빔 경계 및 전파원의 빔 소속을 표시하는 웹 시각화에 필요한 자료를 준비해 주세요.
서버에 있는 코드·설정·교정 자료를 먼저 조사하고, 발견한 근거를 함께 제시해 주세요.
운용 서비스를 재시작하거나 설정·원본 데이터를 수정하지 말고, 별도 출력 폴더에
요약과 추출 결과를 작성해 주세요. 외부로 전송하거나 배포할 필요는 없습니다.

1. 현재 앱 상태와 확인이 필요한 차이
- 표시용 안테나 수: FUS 256, PYC 16, LTN 64, OGW 32.
  설치 안테나 수, 실제 활성 안테나 수, 편파별 입력 수, 디지털 빔 수를 구분해 확인해 주세요.
- 기존 OGW 메타데이터는 16개/2×8 배열입니다. 사용자가 지정한 32개와 다르므로
  최신 배치와 적용 날짜를 확인해 주세요. 32개라고 가정해 배열 모양을 임의로 만들지 마세요.
- FUS는 사용자 제공 CSV로 256개 잠정 모델 셀을 표시하고 있습니다.
  가정은 beam_id = 16 * iy_NS + ix_EW, 0-based index, b0 = -7.5입니다.
  번호 순서, FFT shift/부호, 운용 offset, 비활성 빔, 3° 배열 회전 부호는 미확정입니다.
  CSV의 Az/El에 회전이 이미 포함되었는지 몰라 추가 회전은 하지 않습니다.
- FUS 이외 사이트는 명목 FoV 타원만 표시하며 실제 디지털 빔 경계가 아닙니다.
- 현재 잠정 FoV: FUS/PYC/OGW 60° EW × 90° NS, LTN 70° EW × 80° NS.
- 잠정 지향점: FUS/LTN 천정, OGW 서쪽 18°, PYC 남쪽 16°.
  이 값이 기계적 기울기인지 전자적 조향인지, 어떤 좌표계의 각인지 확인해 주세요.
- 잠정 배열 회전값: FUS -3°, LTN +0.5°, OGW -5.5°, PYC -0.23°.
  앱은 EW(동쪽 +), NS(북쪽 +) 평면에서 반시계를 양수로 사용합니다.
  서버 값의 기준과 부호를 확인하기 전에는 그대로 적용하지 마세요.
- FUS 주파수 정보도 앱 내부에 300–700 MHz와 400–800 MHz가 혼재합니다.
  하드웨어 대역, 실제 관측/검색 대역, 유효 채널 및 플래그를 구분해 주세요.

2. 사이트별로 조사할 자료
각 항목은 확인됨 / 모델·가정 / 미확인으로 구분하고, 파일 경로·설정 키·코드 함수·
버전 또는 commit·적용 UTC 구간을 근거로 붙여 주세요. 자료가 없으면 없다고 명시하세요.

A. 위치와 배열
- 관측소 위도·경도·고도, 좌표 기준(WGS84 등), 고도가 타원체고인지 해발고인지.
- antenna_id별 로컬 ENU 위치(m), 기준점, 측량 날짜, 활성 여부, 입력 채널 대응.
- 배열 방향, 기울기, 행/열 방향, 간격과 비정규 배치, 편파 종류·축 방향.
- 안테나 수와 receiver/input/polarization 수의 정의, 현재 운용 구성 및 결손 소자.

B. 빔 생성·번호·지향점
- 실제 사용하는 beamformer 코드와 설정, 빔 수, EW/NS 빔 인덱스 범위.
- beam_id와 행/열·FFT bin·채널·출력 파일 이름의 대응표.
- FFT sign/shift, delay·phase의 부호, zero-padding, beam spacing,
  기준 주파수 및 채널별 주파수, 가중치/taper, calibration 적용 방식.
- phase-shift 또는 true-time-delay 여부와 주파수에 따른 beam squint 처리.
- steering/offset/boresight의 정의와 회전 순서, 좌표 변환 코드.
- 각 beam의 중심 local Az/El 또는 방향코사인(l,m,n), 주파수와 시각 의존성.
- 비활성·마스킹 빔, 운용 모드별 변경, 좌우/남북 반전과 wrap-around 여부.

C. 실제 빔 폭·응답·경계
- 제공 가능한 측정 beam map 또는 simulation, 생성 방법, 교정 상태와 유효 대역.
- 개별 소자 primary beam, array factor, 최종 station beam 중 어느 것인지 명시.
- 응답이 voltage/amplitude인지 power인지, 선형/dB 단위, 정규화 기준.
- 편파별 또는 합성 편파 응답, 주파수별 응답과 대역 평균 방법/가중치.
- FWHM 또는 -3 dB power contour, 주엽/부엽/grating lobe 구분,
  필요하면 -6/-10 dB contour 및 공통 기준으로 정규화한 sensitivity map.
- 측정 감도 경계와 빔 할당 셀(인접 빔 사이의 구획)을 별도로 제공.
  할당 셀을 실측 FWHM으로 부르거나 안테나 수만으로 빔 폭을 정하지 마세요.
- 소스가 여러 빔에 포함될 때 반환할 전체 beam ID 및 대표 빔 선택 규칙,
  경계 위 점, 수평선 아래, 마스킹 영역 처리 규칙.

3. 좌표와 웹 표시 규약
출력 Az/El은 도 단위로, Az=0° 북쪽, 90° 동쪽, 시계 방향 증가,
El=0° 수평선, 90° 천정으로 통일해 주세요. 원본 규약과 변환식을 함께 남겨 주세요.
관측/기하 고도 및 대기굴절 적용 여부를 구분하고, 시간 의존 자료는 UTC를 명시하세요.
방향코사인은 l=cos(El)sin(Az), m=cos(El)cos(Az), n=sin(El)입니다.
웹은 천정 중심 방위정거도법으로 x=(90°−El)sin(Az), y=(90°−El)cos(Az)를 사용합니다.
따라서 x,y는 방위각/고도 자체가 아닌 투영 각거리 성분입니다.
가능하면 투영 전 Az/El을 제공하고, 이미 적용한 회전·조향을 명시해 중복 적용을 막아 주세요.

4. 요청 산출물 (UTF-8, 단위 명시)
- README: 사이트별 확인 결과, 근거, 알려진 한계, 재생성 명령, 필요한 추가 질문.
- stations.json: 사이트 위치, 안테나 수 정의, 배열/지향/좌표 규약, 모드·유효 날짜.
- antennas.csv: site, antenna_id, east_m, north_m, up_m, polarization, enabled.
- beam_centers.csv: site, mode, valid_from_utc, valid_to_utc, frequency_mhz,
  polarization, beam_id, ix, iy, az_deg, el_deg, l, m, n, enabled, evidence_type.
- beam_contours.csv: site, mode, frequency_mhz, polarization, beam_id,
  boundary_type, level_db, contour_id, vertex_order, az_deg, el_deg.
  boundary_type은 assignment_cell / power_contour 등으로 구분하고,
  할당 셀에는 해당 없는 level_db를 비워 두세요. 분리된 contour는 별도 ID를 부여하세요.
- 원본 응답 맵이 있으면 NPZ/HDF5/FITS 등으로 제공하고 축 순서·단위·좌표·정규화를 설명.
- 추출/계산 스크립트와 의존성, 원본 파일·설정·commit을 연결하는 provenance 목록.
위 필드가 적용되지 않거나 자료가 없으면 null/빈 값과 이유를 기록하세요.
일반 코드를 준비하되, 실제 없는 빔·배열·윤곽 데이터를 만들어 채우지 마세요.

5. 검증 요청
- FUS 0/15/240/255가 각각 어느 방향의 모서리인지 독립적으로 확인.
- 천정 및 북/동/남/서 기준 방향으로 회전 부호와 축 반전 검사.
- beam_id 중복/누락, 활성 빔 수, 각도 범위, contour vertex 순서·폐곡선 검사.
- 각 사이트에서 알려진 보정 전파원 또는 실제 관측 사례의 UTC·주파수를 선택해,
  계산 Az/El 및 예상 beam ID가 운용 기록과 맞는지 비교. 잔차와 불확실성을 보고.
- 최소한 저/중/고 주파수에서 빔 중심과 폭의 변화를 비교하거나 자료 부재를 명시.
- FUS는 현재 모델의 가정과 실제 설정 차이를 표로 정리하고,
  PYC/LTN/OGW는 실제 디지털 빔을 그릴 수 있는지 또는 명목 FoV만 가능한지 결론 제시.

우선 최소 패키지(각 사이트 중심 좌표·번호 대응·좌표 규약·활성 상태·근거)를 확보하고,
응답 맵과 감도 경계는 확보 가능한 범위에서 추가해 주세요.
접근권한이 필요한 자료나 운영에 영향을 주는 작업이 있으면 실행하지 말고 해당 항목을 보고하세요.
반환 문서에는 비밀번호, 토큰, 개인키를 포함하지 마세요.
